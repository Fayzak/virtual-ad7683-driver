# Минимальный SPI-стенд: план реализации

**Цель:** в Linux 6.12.107 провести запрос от драйвера протокола через
`spi_sync()` и SPI core до виртуального контроллера и проверить ответ.
Первый стенд использует собственный тестовый протокол, а не протокол AD7683.

## 1. Файлы и отдельная сборка

Пиши реализацию сразу в `src/spi.c`, а структуры состояния и общие константы —
в `inc/spi.h`, используя существующие заготовки. На время первых тестов этот
код собирается отдельно в `spi.ko`. К `virtual-ad7683.ko` его пока не подключай:
существующие `/dev/ad7683`, таймер, клиентские очереди и ABI остаются прежними.

В корневом `Kbuild` раздели два варианта сборки:

```make
ifeq ($(SPI_STAND),1)
obj-m := spi.o
spi-y := src/spi.o
else
obj-m := virtual-ad7683.o
virtual-ad7683-objs := src/main.o src/params.o src/device.o src/client.o
endif

ccflags-y := -I$(src)/inc
```

В корневой `Makefile` добавь отдельные цели; строки рецептов начинаются с TAB:

```make
.PHONY: build-spi run-spi remove-spi

build-spi:
	$(MAKE) -C $(KERNEL_DIR) M=$(PWD) SPI_STAND=1 modules

run-spi:
	insmod $(PWD)/spi.ko

remove-spi:
	rmmod spi
```

Существующие цели `build`, `run`, `remove` сохраняются. `src/main.c` не входит
в `spi.ko`: единственные `module_init()` и `module_exit()` стенда будут
в `src/spi.c`. Не используй здесь `module_spi_driver()` вместе со своим
`module_init()` — регистрируй драйвер протокола явно.

## 2. Драйвер виртуального контроллера

1. В `inc/spi.h` опиши состояние контроллера: указатель `spi_controller`
   и служебного родителя. Родителя создай через `root_device_register()`.
2. В `src/spi.c` напиши `transfer_one(ctlr, spi, transfer)`. Контракт стенда:
   только RX, `tx_buf = NULL`, `rx_buf != NULL`, `len = 2`. При неверных
   параметрах возвращай `-EINVAL`; при верных запиши `0x12`, `0x34` в RX
   и верни 0 — передача уже закончена.
3. Напиши функцию инициализации контроллера: `spi_alloc_host()`, затем
   `bus_num = -1`, `num_chipselect = 1`, `mode_bits = 0` (только mode 0),
   `bits_per_word_mask = SPI_BPW_MASK(8)`, максимальная частота 1 МГц
   и указатель на `transfer_one`. Опубликуй через `spi_register_controller()`.
4. Не реализуй `transfer_one_message()` и не вызывай finalize из callback:
   SPI core установит стандартный обработчик сообщения, учтет
   `actual_length` и завершит сообщение после возврата 0 или ошибки.
5. Напиши парную очистку: удалить зарегистрированный контроллер через
   `spi_unregister_controller()`, затем родителя через `root_device_unregister()`.
   Для ошибки до регистрации предусмотри освобождение выделенного
   контроллера через `spi_controller_put()`.
6. Временно вызывай только эти функции из init/exit модуля. Собери, загрузи
   и выгрузи `spi.ko`: должен появляться и исчезать контроллер `spiB`.
   На этом этапе периферии и обмена еще нет.

Свои workqueue, таймер, IRQ и DMA здесь не нужны. Очередь сообщений и
`kthread_worker` создает SPI core. Частота 1 МГц — настройка, реальных тактов нет.

## 3. Тестовый драйвер протокола и устройство

1. В `inc/spi.h` добавь состояние протокола с результатом теста. В `src/spi.c`
   объяви `spi_device_id` с именем `vspi-test` и `spi_driver` с `id_table`,
   `.driver.name = "vspi-test"`, `probe`, `remove`. Для проверки при загрузке установи
   `.driver.probe_type = PROBE_FORCE_SYNCHRONOUS`.
2. В `probe()` выдели RX через `kmalloc()`, обнули `spi_transfer`, задай
   `rx_buf` и `len = 2`. Метаданные `spi_message` и `spi_transfer` допустимы
   на стеке, RX-буфер — нет. Инициализируй сообщение через `spi_message_init()`,
   добавь transfer через `spi_message_add_tail()` и вызови `spi_sync()`.
3. После возврата проверь `ret == 0`, `actual_length == 2` и байты `12 34`
   (hex). Собери число как `(rx[0] << 8) | rx[1]`: ожидается `0x1234`.
   Это явно заданный порядок тестовых байтов, не формат `/dev/ad7683`.
4. Отдельным новым сообщением запроси один байт. Ожидай `-EINVAL` и
   `actual_length == 0`; это проверит передачу ошибки от контроллера к клиенту.
   Сохрани итог обеих проверок, выведи результаты в журнал и освободи RX.
   Неожиданный результат должен приводить к ошибке `probe()`.
5. Расширь init модуля: после контроллера вызови `spi_register_driver()`,
   затем `spi_new_device()` с `modalias = "vspi-test"`, CS=0, mode=0
   и `max_speed_hz = 1000000`. Размер слова оставь стандартным — 8 бит.
   SPI core сопоставит имена и
   вызовет `probe()`. Успех создания устройства не гарантирует успех `probe()`:
   отдельно проверь привязку и сохраненный результат теста.
6. Добавь параметр модуля `force_queue`: до регистрации контроллера перенеси
   его значение в `ctlr->must_async`. При 0 свободный контроллер может
   выполнить запрос быстрым путем, при 1 core использует очередь.
   Для `probe()` оба случая остаются синхронным вызовом с одинаковым ответом.

```text
probe() -> spi_sync() -> SPI core (быстрый путь / очередь)
        -> стандартный spi_transfer_one_message() -> наш transfer_one()
        -> RX или ошибка -> SPI core завершает message -> возврат в probe()
```

## 4. Удаление и откат ошибок

Итоговый exit: `spi_unregister_device()` (вызывает `remove()`), затем
`spi_unregister_driver()`, очистка контроллера и родителя из этапа 2.
В `remove()` периодическую работу останавливать не требуется: все запросы
выполнены синхронно в `probe()`. При ошибке init откатывай только успешно
выполненные шаги в обратном порядке; не оставляй устройство с неудачным probe.

## 5. Первые проверки в VM

Выполняй команды из корня рабочей копии в VM с Linux 6.12.107.
Собирай без sudo: `make build-spi`. При другом пути к сборочному дереву:
`make build-spi KERNEL_DIR=/path/to/kernel/build`.
До загрузки сравни `uname -r` и `modinfo -F vermagic ./spi.ko`.
Сохрани `dmesg` до загрузки и после выгрузки, не очищая журнал.

| Этап / команда | Что проверить |
| --- | --- |
| Только контроллер: `sudo make run-spi` | Появился наш `spiB` в `/sys/class/spi_master/` |
| После этапа 3: `sudo make run-spi` | `spiB.0` привязан к `vspi-test` в `/sys/bus/spi/devices/`; результаты: `0 / 2 / 12 34` и `-EINVAL / 0` |
| `sudo make remove-spi` | Объекты стенда исчезли; новых WARN/Oops нет |
| После выгрузки: `sudo insmod ./spi.ko force_queue=1` | Те же результаты через очередь; затем снова выгрузи модуль |

Номер B динамический: находи объекты по нашему родителю и драйверу.
Ожидаемое сообщение об ошибке короткой передачи — часть отрицательного теста.
Успешная проверка SPI не означает проверку настоящего AD7683.

функции `drivers/spi/spi.c` в Linux 6.12.107. Подробнее: [spi-layers.md](spi-layers.md).
